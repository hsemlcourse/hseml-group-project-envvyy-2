# Отчёт CP3: Предсказание популярности Twitch стримеров

## 1. Введение и постановка задачи

**Что мы делаем:** Хотим научиться предсказывать, насколько популярным будет стример на Twitch. Для этого берём данные о канале стримера (сколько у него зрителей, подписчиков и т.д.) и пытаемся угадать общее время просмотра его стримов.

**Какая задача:** Это задача регрессии - то есть мы предсказываем число (в моем случае время просмотра в минутах).

**Зачем нужна такая метрика (RMSE):**
- RMSE показывает среднюю ошибку в предсказаниях
- Она штрафует большие ошибки сильнее, чем маленькие
- Нам это важно, тк если ошибиться в 10 раз - это намного хуже, чем ошибка в 2 раза

## 2. Где взяли данные

**Откуда данные:** Взяли готовый датасет с Kaggle - там лежат данные о стримерах Twitch.

**Что внутри датасета:**
- 1247 стримеров
- Информация: сколько минут стримили, сколько было зрителей (пиковых и средних), сколько подписчиков, на каком языке проводят стримы, есть ли партнёрство, есть ли взрослый контент и тд и тп

**Сколько данных:** Около 1000 строк и 11 колонок - этого достаточно для обучения модели(для крайне точных предсказщаний конечно это чудовищно мало, но датасета который подошел бы мне под задачу с большим кол-вом данных я к сожалению не нашел, простите).

## 3. Как готовили данные

**Шаг 1 - Почистили данные:** Убрали повторяющиеся строки, заполнили пустые места.

**Шаг 2 - Создали новые признаки:** Добавили свои фичи, чтобы модели было проще учиться:
- Соотношение подписчиков к зрителям
- Сколько подписчиков получали за час
- Логарифмы больших чисел (чтобы модели было легче работать с огромными значениями)

**Шаг 3 - Закодировали язык:** Превратили названия языков в числа, чтобы модель могла их понимать.

**Шаг 4 - Убрали выбросы:** Удалили стримеров с аномально большим временем просмотра.

**Шаг 5 - Нормализовали:** Привели все числа к одному диапазону, чтобы модель не думала, что большие числа важнее.

**Разбили данные:** 70% для обучения, 15% для проверки, 15% для финального теста.

## 4. Базовая модель (с чем сравниваем)

Взяли простую модель - линейную регрессию. Она работает "из коробки", без всяких настроек:
- Ошибка (RMSE): около 85000
- Объясняет 85% вариации данных (R2)

Это наш ориентир - если новая модель лучше, значит мы крутые.

## 5. Эксперименты с моделями

Пробовали разные модели и сравнивали их, получили такие результаты:

| Модель | Ошибка (RMSE) | Насколько точная (R2) |
|--------|---------------|----------------------|
| Linear Regression (базовая) | 85000 | 85% |
| Ridge | 82000 | 87% |
| Lasso | 86000 | 84% |
| Random Forest | 45000 | 94% |
| Gradient Boosting (самый топ) | 42000 | 95% |
| XGBoost | 40000 | 95% |
| LightGBM | 38000 | 96% |

**Какую выбрали:** Gradient Boosting из scikit-learn.

**Почему не LightGBM/XGBoost:**
1. XGBoost и LightGBM требуют дополнительных библиотек, которые могут не встать на сервере
2. sklearn Gradient Boosting идёт "из коробки" с Python - никаких лишних зависимостей
3. Разница в ошибке 4000 минут (38000 vs 42000) - это не критично для нашей задачи

По сути все три модели показывают примерно одинаковый результат (95% точность). Gradient Boosting намного проще в установке и деплое, то есть она буквально самая оптимальная для нас.

## 6. Финальная модель и что она поняла

**Наша модель:** Gradient Boosting Regressor

**Что модель поняла (какие признаки важнее всего):**
1. Время стрима - сколько минут стримил стример
2. Средние зрители - сколько народа в среднем смотрело
3. Пиковые зрители - максимум аудитории
4. Полученные подписчики - сколько новых людей подписались

В целом логично - больше стримишь, больше зрителей а значит и больше времени просмотра.

## 7. Как это работает (деплой)

**Что мы сделали:**
- API на FastAPI - сервер, который принимает данные о стримере и возвращает предсказание
- Интерфейс на Streamlit - простая веб-страница, где можно ввести данные и получить результат

**Как запустить:**

Через Docker (рекомендуется):
```bash
docker-compose up --build
```
После этого:
- API: http://localhost:8000/docs (там можно протестить прямо в браузере)
- Интерфейс: http://localhost:8501

Или просто запустить на компьютере(самый удобный способ и на видео представлен именно он):
1. Запустить `restart.bat`
2. Откроются два окна - API и интерфейс

**Что умеет наша система:**
- `/predict` - принимает данные о стримере и возвращает предсказанное время просмотра
- `/health` - проверяет, что система работает
- `/model-info` - показывает информацию о модели
